OPENPAPER — ПЛАН БУДУЩИХ ОБНОВЛЕНИЙ
Текущая версия: 0.0.19

СТРАТЕГИЯ

Диагностика
  → корректность кадров
  → безопасный lifecycle
  → event-driven renderer
  → оптимизация аудио
  → оптимизация UI
  → совместимость
  → безопасность обновлений
  → стабильный релиз

Сначала обеспечиваем измеримость и надёжность. Затем оптимизируем CPU,
энергопотребление и масштабируемость интерфейса.


ЭТАП 1. КОРРЕКТНОСТЬ NATIVE RENDERER

v0.0.18 — честная статистика кадров [ВЫПОЛНЕНО]

Изменения:
- добавить PresentOutcome;
- различать показанный кадр, frame-latency drop,
  DXGI_ERROR_WAS_STILL_DRAWING и слишком поздний кадр;
- увеличивать frames_presented только после настоящего успешного Present;
- не считать renderer готовым после отброшенного первого кадра;
- добавить timestamp последнего успешно показанного кадра;
- добавить decoded, presented и dropped counters;
- измерять first-frame latency.

Критерии готовности:
- renderer не сообщает Ready, пока кадр действительно не показан;
- при отсутствии успешного Present включается libVLC fallback;
- существующие ролики продолжают зацикливаться.

v0.0.19 — надёжный watchdog и fallback [ВЫПОЛНЕНО]

Изменения:
- watchdog первого кадра;
- watchdog зависшего воспроизведения;
- fallback только по подтверждённой неисправности;
- защита от нескольких параллельных запусков fallback;
- отдельные ошибки decoder, presenter, audio, WorkerW и D3D device removed;
- сохранение native video, если сломалось только native audio.

Критерии готовности:
- невозможно получить постоянное состояние «звук есть, видео нет»;
- fallback срабатывает один раз и не создаёт несколько player;
- после отказа аудио видео продолжает работать.


ЭТАП 2. БЕЗОПАСНОЕ УПРАВЛЕНИЕ ДВИЖКОМ

v0.0.20 — Engine State Machine

Состояния:
- Stopped;
- Starting;
- RunningNative;
- RunningHybrid;
- RunningVlc;
- Switching;
- Stopping;
- Failed.

Изменения:
- добавить generation ID для каждого запуска;
- убрать запуск и остановку рендереров из global mutex;
- под mutex выполнять только короткие операции со state;
- устаревший результат запуска автоматически уничтожать;
- запретить предыдущему запросу перезаписывать новый выбор;
- сделать SetWallpaper асинхронным для WPF;
- показать состояние загрузки на выбранной карточке.

Критерии готовности:
- интерфейс не зависает при переключении;
- быстрое нажатие на несколько карточек запускает только последнюю;
- громкость, mute и закрытие доступны во время запуска видео.

v0.0.21 — безопасный lifecycle потоков

Изменения:
- больше не терять JoinHandle;
- добавить stop, pause, resume и configuration-changed events;
- хранить завершающиеся pipelines в состоянии retiring;
- уничтожать HWND только после завершения renderer;
- корректно выполнять Media Foundation flush/shutdown;
- корректно останавливать WASAPI;
- обрабатывать зависшие codec/driver вызовы без блокировки UI.

Критерии готовности:
- после остановки не остаются renderer threads;
- невозможно запустить два renderer на одном HWND;
- приложение стабильно закрывается во время загрузки и fallback;
- 100 переключений не увеличивают количество потоков.


ЭТАП 3. EVENT-DRIVEN MEDIA FOUNDATION

v0.0.22 — ограниченная очередь MF-событий

Изменения:
- заменить неограниченный channel на bounded queue;
- рекомендуемый предел — 256 событий;
- callback использует неблокирующий try_send;
- ограничить количество событий за один pump;
- отбрасывать события устаревшего generation;
- добавить current depth, high watermark и overflow counter;
- при overflow безопасно переходить на fallback.

Критерии готовности:
- память не растёт при потоке событий;
- event storm не останавливает presentation;
- остановка renderer работает при заполненной очереди.

v0.0.23 — waitable video scheduler

Изменения:
- удалить 5-миллисекундный polling;
- использовать waitable timer для presentation timestamp;
- ожидать stop, pause/resume, timer, audio-clock update и media event;
- корректно пересчитывать таймер после паузы;
- сохранить политику отбрасывания опоздавших кадров.

Критерии готовности:
- нет постоянных пробуждений каждые 5 мс;
- видео плавное на 24, 30 и 60 FPS;
- A/V drift не превышает установленный порог;
- paused renderer практически не использует CPU.


ЭТАП 4. NATIVE AUDIO

v0.0.24 — event-driven WASAPI

Изменения:
- убрать 10-миллисекундный polling в паузе;
- добавить audio control event;
- ждать WASAPI render event, stop, pause/resume и volume/mute update;
- не опрашивать atomics без необходимости;
- добавить счётчики underrun и written frames.

Критерии готовности:
- при fullscreen pause аудиопоток не просыпается периодически;
- mute и volume применяются без задержки;
- отключение аудиоустройства не завершает приложение аварийно.

v0.0.25 — PCM ring buffer

Изменения:
- заменить VecDeque<Vec<u8>> на ограниченный кольцевой PCM-буфер;
- переиспользовать память;
- исключить allocation для каждого decoded sample;
- ограничить буфер по времени до 100–250 мс;
- добавить high/low watermark;
- отслеживать underrun и overflow;
- минимизировать количество копирований PCM.

Критерии готовности:
- allocations не растут пропорционально audio samples;
- память стабильна при длительном воспроизведении;
- нет потрескиваний и пропусков;
- не ухудшается синхронизация аудио и видео.

v0.0.26 — бесшовный audio loop

Изменения:
- сначала выполнять seek текущего Source Reader в начало;
- пересоздавать reader только как fallback;
- заранее готовить следующий audio cycle, если seek невозможен;
- синхронизировать timeline offset видео и аудио;
- корректно обрабатывать ролики без аудиодорожки.

Критерии готовности:
- короткие ролики циклически воспроизводятся без слышимого разрыва;
- после 100 циклов A/V sync не уплывает;
- EOF не создаёт постоянные decoder restart spikes.


ЭТАП 5. РЕЖИМЫ ПРОИЗВОДИТЕЛЬНОСТИ

v0.0.27 — реальные режимы производительности

Экономия:
- ограничение presentation до 30 FPS;
- агрессивный drop опоздавших кадров;
- preview запускается с большей задержкой;
- preview может быть ограничен 15–24 FPS;
- минимизация фоновых пробуждений.

Баланс:
- исходная частота до 60 FPS;
- нормальная политика late-frame drop;
- стандартное качество preview.

Качество:
- исходная частота видео;
- более мягкое отбрасывание кадров;
- приоритет плавности;
- полный preview FPS.

Дополнительно:
- передавать performance policy в native renderer;
- менять режим без полного перезапуска;
- отображать фактически применённый режим;
- разделить политику native и libVLC.

Критерии готовности:
- режимы реально отличаются по CPU/GPU и FPS;
- переключение не перезапускает аудио;
- выбранный режим сохраняется после перезагрузки.

v0.0.28 — live scaling

Изменения:
- менять stretch/aspect mode без полного restart;
- пересчитывать destination rectangle;
- пересоздавать только зависимые Video Processor resources;
- не перезапускать decoder и audio;
- для libVLC менять aspect ratio на активном player;
- добавить режимы «растянуть», «вписать» и «заполнить с обрезкой».

Критерии готовности:
- переключение происходит мгновенно;
- звук не прерывается;
- GPU decoder не пересоздаётся.

v0.0.31 — библиотека большого размера

Критерии готовности:

Критерии готовности:

- UI не выполняет длительные операции синхронно.
